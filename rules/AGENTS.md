# Swarm Escalation & Lazy Routing

- **When to use `/swarm` (cost-conscious, autonomous when needed)**: Prefer **not** to use a swarm for simple or straightforward single-agent tasks because swarms are expensive across shared quotas. However, **do not hesitate to start a swarm directly (even without the user typing `/swarm`)** once a task becomes complex and multi-step or **highly parallelizable** (multi-module architecture, shared interfaces, >3 independent parallel slices/files/jobs, subtle concurrency/security bugs, or when a lightweight model like Flash/Hydrogen hits a dead end) so smart models plan and verify while grunt models execute in parallel.
- **Load routing policy only when starting a swarm**: Before calling `swarm{action:"add"}` (whether invoked via `/swarm` or started proactively under the rule above, or when asked to check quota / design a swarm roster), read the `swarm-router` skill (`SKILL.md`) and follow its model routing, cross-quota balancing, thinking-effort, and plan-first rules. Do not read it during normal non-swarm conversations.
