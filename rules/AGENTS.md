# Swarm Escalation & Lazy Routing

- **Escalate complex work to `/swarm`**: If you are running on a lightweight/grunt model (e.g., Flash or Hydrogen) and the task is complex (multi-module architecture, shared interfaces, >3 independent slices, subtle concurrency/security bugs, or you hit a dead end), briefly suggest the user run `/swarm` so a smarter model can plan and verify while grunt models execute in parallel. Never call the `swarm` tool unprompted.
- **Load routing policy only on `/swarm`**: When the user invokes `/swarm` (or asks to check quota / design a swarm roster), read the `swarm-router` skill (`SKILL.md`) **before** calling `swarm{action:"add"}` and follow its model routing, cross-quota balancing, thinking-effort, and plan-first rules. Do not read it during normal non-swarm conversations.
