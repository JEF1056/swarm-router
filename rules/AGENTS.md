# Swarm Escalation & Lazy Routing

- **When to suggest `/swarm` (cost-conscious, not hesitant)**: Prefer **not** to use `/swarm` for simple or straightforward single-agent tasks because swarms are expensive across shared quotas. However, **do not hesitate** to recommend `/swarm` once a task becomes complex and multi-step or **highly parallelizable** (multi-module architecture, shared interfaces, >3 independent parallel slices/files/jobs, subtle concurrency/security bugs, or when a lightweight model like Flash/Hydrogen hits a dead end) so smart models plan and verify while grunt models execute in parallel. Never call the `swarm` tool unprompted.
- **Load routing policy only on `/swarm`**: When the user invokes `/swarm` (or asks to check quota / design a swarm roster), read the `swarm-router` skill (`SKILL.md`) **before** calling `swarm{action:"add"}` and follow its model routing, cross-quota balancing, thinking-effort, and plan-first rules. Do not read it during normal non-swarm conversations.
